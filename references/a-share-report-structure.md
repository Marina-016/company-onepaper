# 报告结构与写作规范

本文件定义公司一页纸的完整报告结构、各节写作要求和通用写作规范。

---

## 报告标题格式

```
{股票简称}（{股票代码}）公司一页纸：{一句话结论}
```

示例：
```
贵州茅台（600519）公司一页纸：直销渗透加速叠加批价修复预期，高股东回报
```

- **股票简称**：取自 `getFdmtMoStdItem` 接口返回的 `secShortName` 字段（`report_writer.py` 自动提取）
- **一句话结论**：约20字（最多25字），须在语义完整处自然结尾，**严禁句子中断**，体现最核心驱动力或投资判断，有明确观点导向

## 通用写作规范

- **数据精确性**：历史财务数据必须使用接口返回的真实数字，**严禁"约"、"大约"、"估计约"等估算表述，也严禁定性化表述代替具体数字**（如"收入有所增长"须改为"收入增长X.X%至X.XX亿元"）
- **机构名称规范**：正文叙述中不得出现具体券商/机构名称（如"中信证券"），统一用"头部券商"、"主流机构"等；**例外：第9.2节盈利预测表格中直接展示机构真实名称**；机构来源同时在参考资料列出
- **角标引用**：**全文所有章节**关键数据、重要判断均须行文中用方括号标注来源 `[N]`（如"营收同比增长23.5%[1]"），字体与正文一致，不使用上标；**估算数据（含情景推演假设数字、模型推断结果、未来预测）也必须标注引用**——若数字直接来自研报/纪要/接口则标注对应序号，若为基于已有数据推算则注明"基于[N]推算"；参考资料章节提供完整来源列表
- **表格引用位置铁则**：`[N]` 必须紧跟在**具体数值**（数字、百分比、金额等）后面，**严禁**挂在以下非数值列：机构名称（如 `Wolfe Research[5]`）、指标名称、行标题、评级标签、假设描述。简记：**引用只跟数字，不跟名称或描述**
- **列表标记规范（v1.2.9）**：正文列举项**统一使用 `•` 无序符号**，顶格无缩进；严禁 `1）2）3）`、`-`、`*` 混用；此项由 `_normalize_bullet_markers` 自动归一化，`markdown_to_docx.py` 保证 Word 中 `•` 行零缩进
- **正文缩进规范（v1.2.8-R1）**：所有小节标题下方的正文段落**严禁前导缩进空格**；正文首字符必须顶格（标题、表格、列表、代码块除外）。此项在生成后由 `_dedent_body_paragraphs` 自动修复
- **调研问答格式（v1.2.9）**：§4.5 机构调研核心问答使用 `**Q：**` / `**A：**` 加粗标签，每对 Q&A 分两行独立输出；Q 与 A **严禁挤在同一行**；A 末尾截断标注 `…[内容截断]`。此项由 LLM prompt 显式要求 + `_normalize_survey_qa_markdown` 自动兜底
- **内容深度**：不止于数据罗列，需有判断、量化分析和洞见；涉及具体事件时尽量给出数据支撑
- **表格格式铁则**：
  - 🚨 每张表格列数上限：数据表 ≤ 8 列，同业对比表 ≤ 10 列；超出必须精简合并
  - 🚨 **公司+代码合并**：任何表格中涉及公司名和代码的，**必须合并为一列**，格式 `公司名（代码）`（如 `贵州茅台（600519）`），**严禁**将"公司"和"代码"分两列
  - 🚨 参考资料章节**必须用纯文本列表**（每条 `[N] 类型 | id | 日期 | 机构 | 标题`），**严禁使用 Markdown 表格**
  - 表格对齐：统一左对齐 `:--`，数字列可居中 `:--:`
  - **Word 合并规则**：生成 Word 时，所有表格首列中**连续相同**的单元格会自动纵向合并（跳过表头）；若需要合并"指标/类型/情景"等首列，请在 Markdown 中连续重复完全相同的首列文本，不要用空白单元格占位。
  - 列标题保持简短（2-6字），把空间留给数据

**数据获取优先级（v1.2.3 强制执行）**：
关键数据必须按以下顺序逐级获取 → 前一级无数据才进入下一级：
1. Datayes 结构化接口 → 2. Materials V2 → 3. Datayes 研报全文 → 4. 研报图表及说明 → 5. 公告/纪要/公司披露 → 6. 公司官网/交易所/IR 等公开来源
⛔ 严禁第一级无数据即跳过；公开来源须写入 materials JSON 的 `external_sources` 后方可进入引用链路。

**稀疏行列处理（v1.2.3 强制执行）**：
完成全部搜索后仍缺数据时执行以下规则：
- 一行 ≤1 个有效数据 → 删除整行
- 一列 ≤1 个有效数据 → 删除整列
- 删除后不足 2 个有效指标或 2 个比较维度 → 删除整张表
- ⛔ 不得输出大量 `—`、`N/A`、空格或"待补充"
- ⛔ 不得编造数据
- ⛔ 不得在注释中写"已隐去""因数据不足删除"
- 纯定性表格（无数值列）不适用上述稀疏规则

## 章节标题序号规范（v1.2.3 强化）

- 一级章节（H2）：`## 1 公司近况跟踪`、`## 2 核心投资逻辑` 等，编号与模板严格一致
- 二级章节（H3）：`### 2.1 短期逻辑`、`### 2.2 长期逻辑` 等，**编号必须继承所属 H2 的编号**——父 H2 编号=2，则子 H3 编号必须以 `2.` 开头
- 三级章节（H4）：`#### 2.1.1 [标题]` 等（如需要），继承 H3 编号
- ⛔ **严禁**父子编号不一致：如 `## 3 核心投资逻辑` 下出现 `### 2.1 短期逻辑`（父=3，子却以 2 开头）
- 同级小节编号连续、不重复、不倒序
- 输出前逐章验证：每个 H3 编号前缀 = 其上方最近 H2 的编号

正确示例：
```text
## 2 核心投资逻辑
### 2.1 短期逻辑
### 2.2 长期逻辑
```

错误示例（禁止）：
```text
## 2 核心投资逻辑
### 2.1 短期逻辑
### 3.2 长期逻辑    ← 错误：与 H2 编号不一致
```

## 1 公司近况跟踪 ⭐⭐⭐（最重要，置于最前）

**写作要求：**
- **总字数严格控制在400字以内**，不设二级章节，如需分点用无序符号（`•`）
- 聚焦过去1-3个月最重要的3-4个事件/变化，**快速总结要点，不展开细节**
- 每个要点仅说明：发生了什么 + 关键数字 → 一句话市场解读；细节分析放到第2节/第3节
- **内容边界（严格遵守）**：
  - 有投资参考价值的深层逻辑 → 移至第2节
  - 可量化的未来时间节点事件 → 移至第3节
  - 业绩说明会、路演等会议内容 → 仅保留结论性表态，不展开会议细节
  - **本节只保留已发生的近期动态事实，不做预测或深度分析**
- **倒数第二段**：用一句话包含当前市场评级（主流机构评级方向）、目标价区间、当前PE/PB；不标注具体机构名称
- **最后一段**：用一句话简要说明市场一致预期未来三年的营收和归母净利润预测数值，标注来源`[N]`；**不展开分析，仅陈述数字**
- 所有数据须标注引用 `[N]`

示例格式：
> • 公司近期[发生了X事件]，[具体数字]。[一句话解读]。[1]
> • [另一事件]，[具体数字]，[一句话解读]。[2]
> 当前主流机构维持买入评级，目标价区间X-X元，现价对应PE约Xx/PB约X.Xx。

## 参考资料（v1.2.3 统一格式）

**🚨 格式铁则：必须用纯文本列表，严禁使用 Markdown 表格。每条独占一行。`[序号]` 后不加空格。**

**引用序号规范**：全文每个独立来源分配唯一序号，序号不重复——即使同一篇研报多处引用，仍只占一个序号。序号按文中首次出现顺序递增。

**研报机构名称**：来自接口返回的真实机构名，从 JSON 逐字复制。

参考资料按文中引用顺序列出，每条格式固定为：

```text
[N]来源类型 | YYYY-MM-DD | ID：真实ID | 机构 | 完整标题 | API：接口名
```

来源类型分五类：
- `Materials V2研报` / `Materials V2纪要` / `Materials V2市场观点` / `Materials V2微信`
- `Datayes研报`（来自 batchGetReportContent）
- `Datayes公告`（来自 announcement / getAnnouncementDetail）
- `Datayes纪要`（来自 meeting_search / getMeetingSummaryDetail）
- `Datayes结构化接口`（无 ID 则省略 `ID：` 字段）

完整示例：

```text
[1]Materials V2研报 | 2026-03-15 | ID：8464540 | 机构名称 | 示例公司产品周期点评标题 | API：getMaterialsV2
[2]Datayes研报 | 2026-03-12 | ID：8456789 | 中信证券 | 公司深度报告：关注AI商业化进展 | API：batchGetReportContent（研报全文）
[3]Datayes纪要 | 2026-02-20 | ID：M20260220001 | 国泰君安 | 公司2025年度业绩交流会 | API：getMeetingSummaryDetail
[4]Datayes公告 | 2026-03-10 | ID：A20260310001 | — | 关于XX事项的公告 | API：getAnnouncementDetail
[5]Datayes结构化接口 | 2025-12-31 | API：fdmtNew（财务摘要，2024年报）
[6]公开网页 | 2026-06-15 | 公司官网 | 2026年Q1运营数据 | https://ir.example.com/...
```

字段顺序固定：`[N]` → 来源类型 → 日期 → `ID：`值（可选） → 机构 → 标题 → `API：`值（结构化接口仅写 API）。

所有元数据必须从本次 materials JSON 逐字复制。⛔ 严禁：
- `[1] Materials...`（序号后加空格）
- 使用 `SRC-1` 等内部编号
- 改写标题或机构名
- 省略任一字段（结构化接口无 ID 可省略 ID 字段、无机构可写 `—`，其余必填）
- 将参考资料写成表格或项目符号
- 为公开来源伪造材料 ID

公开网页来源格式：`[N]公开网页 | YYYY-MM-DD | 发布方 | 标题 | URL`
