# 港美股质量检查清单

交付前按本清单检查 Markdown 和 DOCX。正文不应出现内部 pipeline、checker、quality gate、P0/P1/P2 等工程话术；诊断信息只写入 JSON 或最终进度说明。

## 1. 交付物与结构

- 已生成 Markdown 和 Word（DOCX）两个版本，不只在对话里输出正文。
- 标题下方只展示市场和生成日期；港美股头部不展示行业、当前价格或市值。
- 第 1 章为 `关键要点`，没有尾部 `Key Takeaways` / `Investment Takeaways` 之类重复章节。
- 原模板顺序不变；空章节省略后，最终 H2/H3 按展示顺序连续重编号，同级连续无重复。
- 若有章节省略，`generation_status.json` 记录 `section_number_mapping`、`omitted_original_sections`、`display_sections_total` 和 `reference_display_section`。
- 最终正文没有空壳章节、空表格、只有“数据来源”的章节、占位说明或接口错误日志。

## 2. 来源与引用

- `getMaterialsV2` 至少覆盖近况/催化、投资逻辑、业务财务、产销生态、估值分歧、市场关注六类 query。
- 研报、会议纪要、公告优先读取详情/全文；避免只用列表摘要写正文。
- 若正文引用公开新闻或公开 URL，该来源已写入 materials JSON 的 `external_sources`，并包含标题、日期、发布方、URL 和正文快照。
- 正文出现的每个 `[N]` 都能在参考资料章节找到定义；参考资料中的每个 `[N]` 都被正文实际引用。
- 每条参考资料都能回溯到 materials JSON 的真实来源实体或结构化接口；`refs_missing=0`、`refs_synthetic=0`。
- 参考资料标题、机构、日期与 JSON 原始元数据逐字一致，不截断、不改写、不替换来源类型。
- Materials V2 来源按实际引用逐条列出，不能合并成笼统来源。

## 3. 数据与口径

- 历史财务数据优先使用结构化接口；港股优先 `getHkFdmtIsPit`、`getHkFdmtBsPit`、`getHkFdmtCfPit`。
- 美股没有 HK PIT 三表接口；财务数据只能从研报全文、图表、财报点评、公司公告/IR 材料抽取。缺结构化三表时，诊断文件可记 `skipped_with_reason` / `N/A`，正文不得用 `N/A` 充数。
- 缺失数据已按结构化接口 → Materials V2 → 研报全文 → 研报图表 → 公告/纪要/公司披露 → 公开来源逐级尝试。
- `Actual`、`Forecast`、`Guidance`、`Estimate` 清楚区分；来源为预计/预测/指引/目标价/情景假设时，正文保留属性，不改写为已发生事实。
- FY/CY、季度/自然年、人民币/港元/美元、普通股/ADS 口径保持一致。
- GAAP / non-GAAP / IFRS / 经调整口径不混用；资本开支区分公司披露 CapEx、研报口径 CapEx、现金流量表“购建长期资产支付现金”。
- ROE 使用常规定义或接口直接披露值；若用替代算法，指标名改为具体算法。
- 正文无无来源市场份额、客户数量、盈利预测、目标价、估值倍数或情景数字。

## 4. 表格与占位符

- 普通数据表列数 ≤ 8，同业对比表列数 ≤ 10。
- 公司名和代码合并为一列，格式 `公司名（代码）`，不拆成“公司”和“代码”两列。
- 结构化表格完成检索后执行稀疏处理：行 ≤1 个有效值删行，列 ≤1 个有效值删列，删除后不足 2 个有效指标或 2 个比较维度则删表；纯定性表不适用。
- 正文不大面积出现 `—`、`N/A`、空格、`待补充`、`未披露`、`未提供`、`无数据`、`已隐去`、`因数据不足删除`。
- 引用位置紧跟具体数值，不挂在机构名、指标名、行标题、评级标签或假设描述上。
- 单元格引用只放本单元格对应来源，不把整行引用复制到所有单元格；同一单元格内引用去重。

## 5. 章节专项

- §2 近况跟踪每条 bullet 以 `**加粗关键词**` 开头，包含具体数字或明确事实，并带 `[N]` 引用。
- §4 催化事件时间表必须有有效表格，同时覆盖近期已发生验证事件和未来可跟踪催化；不把券商评级、目标价调整当作催化。
- §5.2 优先输出近三年已完成年度 actual 分业务收入/占比/毛利率；没有最近一年收入或占比时，不硬造表格，改为 `§5.2 业务深度` 分点叙述，分点小标题加粗。
- §6 产销链与生态目标至少 4 行；3 行可作为 partial 输出；少于 3 行或证据不足应 fail closed，不做通用补行。
- §8 美股只写“市场关注”，不输出“调研问题/调研大纲”；港股市场关注后输出 3-4 个调研议题，每题 2-3 个可量化问题。
- §9 行业对比必须是正式 Markdown 表，列名为 `竞争关系|公司（代码）|市场|可比业务|行业地位|相关业务进展|商业模式|目标客户群体|核心产品`。
- §9 目标公司必须第一行且只出现一次；至少 3 家非目标 peer；每家 peer 有独立 peer-specific 来源，且引用证据包含该 peer 公司名或 ticker。客户、供应商、合作方、投资方、未上市主体不得作为 peer。
- §10 市场分歧主路径为 3 行五列表：`多头观点|多头证据|空头观点|空头证据|需要观察的验证点`；compact short retry 可接受 2 行 partial。不使用确定性原文摘录兜底。
- §10 每行围绕同一主题形成真实多空对立；证据有事实、数字或时间节点；验证点是未来可观察的数据、公告或事件。
- §11 输出时，盈利预测、估值分析、情景推演都必须有可回溯目标价/预测样本或关键假设；不得编造概率、目标价区间、敏感性数字或无来源估值结论。
- §11.2 若机构盈利预测表所有数据行都是占位/空值，应由 writer 省略本节或整章并重编号。
- §12 风险提示使用最新报告期数据；若使用旧期数据，说明原因。

## 6. 时效与合规

- Materials V2 和研报全文优先近 1 个月内容；超过 6 个月的来源仅在无替代时使用，并在 source_trace 标注 `old_source_reason`。
- 估值、预测、催化、行业景气度引用超过 6 个月且无原因时不通过。
- 不调用停用接口：`research_sec_foredata`、`stock_evaluationAnalysis`、`diagnosis_valuation_rank`、`Stock_OnePage`、`market_snapshot`、`market_HK`。
- 正文避免频繁出现具体券商名；参考资料可保留真实来源。
- 若正文观点不是来自具体机构材料，用“解读：”承接，不写“买方认为/机构认为”。
