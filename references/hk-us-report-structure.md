# 报告结构

报告默认中文，控制为"买方一页纸"的密度：结论优先、表格精炼、每节有数据支撑。

**通用规则**：
- **数据精确性**：历史财务数据必须使用接口返回的真实数字，**严禁"约""大约""估计约"等模糊表述**，也严禁定性化代替具体数字（"收入有所增长"→必须"收入增长X%至$XX亿"）
- **机构名称规范**：正文叙述不得出现具体券商/机构名称，用"头部机构""主流机构"代替；§11 仅输出盈利预测、估值分析和情景推演，不再输出逐机构目标价汇总表。
- **序号规范**：正文列举项使用 `1）2）` 或 `•`，**严禁 `1、2、3` 中文序号**

**引用标注位置规则**：
- `[N]` 必须紧跟在**具体数值**（数字、百分比、金额、倍数等）后面，如 `675[5]`、`+12.3%[1]`
- **严禁**将引用挂在以下非数值列：机构名称、指标名称、行标题、评级标签、假设描述
- 简记：**引用只跟数字，不跟名称或描述**
- **引用完整性硬门槛**：正文引用集合必须全部出现在参考资料章节中；缺章重编号后参考资料编号可能不是 §13。若正文出现未定义编号，报告不得交付。
- **来源实体硬门槛**：每个参考资料编号必须能回溯到 materials JSON 的来源实体或结构化接口；禁止新增不存在的 `[N]`。

**事实属性规则**：
- `Actual`、`Forecast`、`Guidance`、`Estimate` 必须分开写。来源文字为"预计/预期/有望/目标价/预测/或将"时，正文必须保留这些限定词。
- 禁止把预测写成已发生事实，例如来源只写"预计推出"，正文不得改写为"已发布/已上线/已实现"。

**章节编号规则（v1.2.4 强制执行）**：
- 生成顺序仍按原模板 §1-§13，但空章节必须省略。
- 任一章节省略后，后续 H2/H3 必须按最终展示顺序连续重编号，不保留跳号。
- H3 编号必须继承最终展示 H2 的编号（如展示 H2=## 3 核心投资逻辑，则 H3=### 3.1 短期逻辑、### 3.2 长期逻辑）。
- `generation_status.json` 必须写入 `section_number_mapping`、`omitted_original_sections`、`display_sections_total` 和 `reference_display_section`。
- ⛔ 严禁父子编号不一致（如 `## 3` 下出现 `### 2.1`）。
- 同级小节连续、不重复、不倒序。

**LLM 任务边界（v1.2.4）**：
- §1 和 §2 作为同一小任务生成，标题结论只来自该任务的 `title_conclusion`。
- §3 分为短期和长期两个并行小任务；任一侧失败时，允许一次合并短重试。
- §4、§5、§6、§7 分别作为独立小任务生成；港股 §7 仍优先走 PIT 三表确定性路径。
- §8 独立生成：港股包含“市场关注 / 调研大纲”，美股只包含“市场关注”。
- §9 由 LLM 生成正式 peer 表，但必须通过 peer-specific 引用证据校验；不足时 fail closed。
- §10 拆成 `section_10_a` 与 `section_10_b` 两个小任务，最终合并为五列表；合并失败时只允许 compact short retry，不做确定性摘录兜底。
- §11 使用目标价/预测记录和一次 LLM 渲染；若 LLM 失败且没有可追溯估值锚，省略并重编号。
- §12 独立生成，格式为加粗风险标题 + 一句具体解释。
- 输出前逐章验证

**缺数据时的处理规则（v1.2.3 强化）**：

- **数据获取优先级**：Datayes 结构化接口 → Materials V2 → Datayes 研报全文 → 研报图表及说明 → 公告/纪要/公司披露 → 公司官网/交易所/IR 等公开来源。严禁第一级无数据即跳过；公开来源须写入 materials JSON 的 `external_sources`。

- **稀疏行列处理**：完成全部搜索后仍缺数据时，行 ≤1 个有效数据删行，列 ≤1 个有效数据删列，删除后不足 2 个有效指标或 2 个比较维度则删表；纯定性表格不适用。
- **占位符处理**：不得输出大量 `—`、`N/A`、空格、"待补充"，不得编造数据，不得在注释中写"已隐去""因数据不足删除"。

正文中若某数据点确实无法获取，使用具体说明代替（如"FY2025 分业务数据未在公开材料中获取"），**严禁出现 `—`、`N/A`、`未披露` 等空白填充**。

**表格格式铁则**：
- 🚨 每张表格列数上限：普通数据表 ≤ 8 列，同业对比表 ≤ 10 列；超出必须精简合并
- 🚨 **公司+代码合并**：任何表格中涉及公司名和代码的，**必须合并为一列**，格式 `公司名（代码）`（如 `{公司名}（{ticker}）`），**严禁**将"公司"和"代码"分两列
- 🚨 参考资料章节**必须用纯文本列表**，**严禁使用 Markdown 表格**
- 表格对齐符号统一使用 `:--`（左对齐），中间列用 `:--:`（居中）仅限数字列
- **Word 合并规则**：生成 Word 时，所有表格首列中**连续相同**的单元格会自动纵向合并（跳过表头）；若需要合并"指标/类型/情景"等首列，请在 Markdown 中连续重复完全相同的首列文本，不要用空白单元格占位。
- 列标题保持简短（2-6字），把空间留给数据

## 标题

标题按市场区分：

**港股**：
```text
# {公司名}（{ticker}）港股公司一页纸：{一句话结论}
```

**美股**：
```text
# {公司名}（{ticker}）美股公司一页纸：{一句话结论}
```

- **一句话结论**：约20字（最多25字），须在语义完整处自然结尾，**严禁句子中断**，体现最核心驱动力或投资判断

标题下方放一行信息，港美股仅展示市场和生成日期：

```text
市场：{港股/美股} | 生成日期：{YYYY-MM-DD}
```

## 1 关键要点

用 4 条中文结论直接回答：

- 为什么现在值得看？
- 最大上行来自哪里？
- 最大下行来自哪里？
- 下一次需要跟踪什么？
- 市场当前定价的核心分歧是什么？

写法要求：每条必须是投资结论，不是摘要复述；尽量包含可验证指标，并标注来源 `[N]`。

## 2 近况跟踪

400 字以内，不设二级标题，列 4 条过去 1-3 个月最重要变化。

**🆕 句首加粗规范（v1.2.4 强制执行）**：
每条 bullet 必须用 `**加粗关键词**` 开头，后跟具体描述。格式：

```text
• **关键词**：[发生了什么]，[具体数字]。[一句话解读]。[N]
```

要求：
- 每条近况必须有加粗关键词
- 必须有数字或明确事实
- 必须有引用 `[N]`
- 不能只有泛泛描述（如"营收表现良好""增长符合预期"）

正确示例：
```text
• **业绩超预期**：FY2026Q4营收950亿美元[5]，同比增长12%，超出彭博一致预期3个百分点。
• **AI产品放量**：Copilot付费用户突破8000万[6]，ARR贡献占比提升至15%。
• **监管落地**：欧盟AI法案7月生效[7]，公司已获首批合规认证，短期无明显增量成本。
```

错误示例（禁止）：
```text
• 公司近期发布了新产品，市场反应积极。  ← 无加粗关键词、无数字、无引用
• 营收表现良好，利润稳定增长。           ← 泛泛描述，无具体事实
```

内容要求：
- 最新业绩/指引/订单/产品/监管/资本开支变化。
- 一句话说明市场解读。
- 最后一段写主流评级、目标价区间、估值区间或一致预期变化。

## 11 估值与预测

**第 11 章图表分析铁则**：本章每张 Markdown 表格或图表后，必须紧跟一段中文文字分析，长度控制在 20-300 字；分析必须解释表内数据的投资含义、分歧来源或后续验证点，不得只复述表头或泛泛总结。

### 11.1 盈利预测

基于结构化一致预期、机构盈利预测抽取、研报预测表格或摘要中明确披露的预测数字确定性生成；本节不得使用目标价、评级或目标价统计结果生成营业收入、净利润或 EPS 预测。

输出一张聚合后的预测表，不展示逐机构大表：

```text
| 预测指标 | FY2027E | FY2028E | FY2029E |
|:--|:--|:--|:--|
```

聚合键为指标、预测年份、币种、单位、会计口径和 FY/CY 口径；至少 3 家独立机构才取中位数。GAAP/non-GAAP、FY/CY、港币/美元/人民币、元/股/元/ADS 不得混合。少于 2 个有效指标或少于 2 个有效预测年份时隐藏整节。

## 13 参考资料（v1.2.3 统一格式）

**🚨 格式铁则：必须用纯文本列表，严禁使用 Markdown 表格。`[序号]` 后不加空格。**

按引用编号列来源，每条独占一行，固定格式：

```text
[N]来源类型 | YYYY-MM-DD | ID：真实ID | 机构 | 完整标题 | API：接口名
```

字段顺序固定：`[N]` → 来源类型 → 日期 → `ID：`值 → 机构 → 标题 → `API：`值。

来源类型映射：
- `Materials V2研报` / `Materials V2纪要` / `Materials V2市场观点` / `Materials V2微信`
- `Datayes研报`（来自 batchGetReportContent）
- `Datayes公告` / `Datayes纪要`
- `Datayes结构化接口`（无 ID 则省略 `ID：` 字段）

完整示例：

```text
[1]Datayes研报 | 2025-09-05 | ID：6399039 | 机构名称 | 示例公司季度报告点评标题 | API：batchGetReportContent（研报全文）
[2]Datayes结构化接口 | 2025-09-30 | API：getHkFdmtIsPit（港股利润表Point in time）
[3]Materials V2研报 | 2026-03-15 | ID：8464540 | 机构名称 | 示例公司产品周期点评标题 | API：getMaterialsV2
[4]Materials V2纪要 | 2026-05-21 | ID：19851 | 机构名称 | 示例公司业绩交流纪要标题 | API：getMaterialsV2
[5]公开网页 | 2026-06-15 | 披露平台 | 示例公司公开披露文件标题 | https://www.example.com/...
```

**Materials V2 引用规则**：
- 脚本生成的 JSON 中 `materials_v2.unique_sources` 字段包含所有去重后的独立来源，每个来源含 `id`、`type`、`title`、`organization`、`publishTime`、`url`
- **每个在报告中实际引用到的 Materials V2 来源必须单独列一条**，按首次引用顺序分配 `[N]`，**严禁**将所有 Materials V2 内容合并为一个笼统引用
- 格式：`[N]Materials V2{类型} | {日期} | ID：{id} | {机构} | {标题} | API：getMaterialsV2`
- 数据类型的映射：`research` → "Materials V2研报"、`meetingSummary` → "Materials V2纪要"、`marketView` → "Materials V2市场观点"、`wechat` → "Materials V2微信"
- ⛔ **标题 & 机构禁止改写**：`title` 字段必须从 JSON **逐字复制**（含所有括号、标签、前缀后缀如 `【机构研报】`），`organization` 字段也必须逐字复制（若 JSON 中 `organization` 为空则取 `source` 字段；两者皆空才写来源类型如"微信"），**不得将类型标签或来源类型名称填入机构字段**。唯一允许的变换是将 research.details 中的 `orgName` 映射为常用简称（如 花旗集团→Citigroup），但标题保持原样。
- ⛔ **Datayes研报（research.details）同适用**：`articleTitle` 和 `orgName` 必须从 JSON 逐字复制，**禁止截断、去掉重复前缀、去掉副标题、去掉括号内补充信息**。

**公开网页来源**：`[N]公开网页 | YYYY-MM-DD | 发布方 | 标题 | 完整URL`。不得伪造材料 ID。

**🚨 引用 ID 校验铁则**：
- 每条 `[N]` 在写入参考资料章节前，**必须在 materials JSON 中按 `id` 反查来源实体**，确认 `title`、`organization`、`publishTime` 与实际引用的内容匹配后才落笔
- ⛔ **禁止**凭记忆、就近套用或自增 ID；禁止将 research_search 列表的序号当作引用 ID
- 研报引用（research.details）的 ID 来自 `articleId` 字段；Materials V2 引用（unique_sources）的 ID 来自 `id` 字段；结构化数据引用标注接口名（如 `getHkFdmtIsPit`）
- **写入参考资料时，`title` 和 `organization` 从 JSON 逐字复制，不做任何改写、截断、去掉前缀/后缀/标签、或把类型标签挪到其他字段**。标题中含 `【机构研报】` 前缀就原样保留，机构名 JSON 是 `cwamcc` 就写 `cwamcc`。
- 若引用公开 URL，必须在 materials JSON 的 `external_sources` 中有离线快照字段；只有 URL、没有标题/日期/发布方/正文快照的来源，不得用于离线 replay 报告。
- 交付前必须执行"正文引用集合 ⊆ 参考资料编号集合"检查；不满足时先修复正文或补齐真实来源。

**🆕 双向闭环检查（v1.2.3）**：正文引用集合 ⊆ 参考资料集合，且参考资料集合中每条均被正文使用（无死引用）。

## 特殊行业适配（v1.2.3）

### 保险公司

不机械使用普通工业企业模板。优先指标体系：

| 维度 | 优先指标 |
|:-----|:--------|
| 新业务 | NBV / VONB、APE、VONB Margin、年化新保费 |
| 存量价值 | EV / Group EV、EV Growth（Return on EV + NBV contribution） |
| 盈利 | OPAT（营运利润）、保险服务收入、保险服务费用 |
| 偿付能力 | 核心偿付能力充足率、综合偿付能力充足率 |
| 投资 | 净/总投资收益率、投资资产配置 |

估值优先方法：
- P/EV（或 P/Group EV）
- 新业务价值倍数
- 内含价值增长拆解
- 股息率和资本回报

材料不足时减少表格数量，**严禁**用毛利率、库存周转、普通 PE 等不适用指标强行填充。

### 其他特殊行业

根据商业模式选择适配指标体系：

| 行业 | 优先指标 | 优先估值 |
|:-----|:--------|:--------|
| 银行 | NIM、不良率、拨备覆盖率、ROA/ROE、CET1、贷存比 | P/B、ROE-P/B |
| 科技/平台 | GMV/TR、MAU/DAU、ARPU、take rate、云收入/利润率、seat/NDR | P/S、EV/EBITDA、SOTP |
| 资源/周期 | 商品价格弹性、现金成本曲线、储量/资源寿命、产量指引、股息率 | EV/EBITDA、P/NAV |
| REITs | DPU/分派率、NPI margin、出租率、WALE、资产负债率 | P/NAV、股息率 |
| 生物医药 | 管线进度、峰值销售、专利到期、研发费用率、现金跑道 | rNPV、DCF、P/S |

不确定时参考该行业主流卖方研究框架选取指标，**严禁**将不适用指标强行填充。
