# 一页纸报告核验提示词

对目标报告执行以下逐项核查，发现问题逐条列出，不得跳过任何步骤。

---

## 一、引用完整性核验（最关键）

### 1.1 正文引用编号遍历

- [ ] 提取报告中所有 `[N]`（正则：`\[(\d+)\]`），去重排序得到引用编号集合。
- [ ] 逐一在"参考资料"章节中查找每条编号，确认存在对应条目。
- [ ] 检查是否有编号跳跃（如 1→3→5 中间缺 2、4），若有则标注"缺失引用 [X]"。
- [ ] 检查是否有参考资料条目从未在正文被引用（死引用），标注"未引用条目 [X]"。

### 1.2 引用内容匹配

- [ ] 对于每个 `[N]`，找到其在文中的**前后句**，提取该句包含的**关键事实**（数字/日期/机构/观点）。
- [ ] 逐一核对：该事实是否与参考资料条目描述一致——条目中的机构名、日期、标题应能支撑该事实。
- [ ] 特别注意：若正文写"Q1 OSG +10%[8]"，则参考资料[8]的标题/来源必须涉及Q1业绩/OSG增速；不能是一篇无关研报。

### 1.3 ID 真实性核验

- [ ] 打开对应的 `*_materials.json`（采集脚本产出的素材文件）。
- [ ] 逐条比对参考资料中的 ID：
  - 研报类型（Datayes研报）→ 在 `research.details` 中搜索该 `articleId`，确认 `orgName`、`publishTimeReadable`、`articleTitle` 是否一致。
  - Materials V2 类型 → 在 `materials_v2.unique_sources` 中搜索该 `id`，确认 `organization`、`publishTime`、`title` 是否一致。
- [ ] 标注："[N] ID=XXXXX 在 JSON 中找不到"、"ID=XXXXX 的机构名在 JSON 中为 YYY，报告中写的是 ZZZ"。
- [ ] **标题逐字比对**：报告中的标题（title/articleTitle）是否与 JSON 原始字段**逐字一致**——含所有括号、标签前缀（如 `【机构研报】`）、重复的公司名/代码前缀、分号分隔的副标题等。凡有差异（截断、去前缀、改写）一律标注。
- [ ] **机构逐字比对**：报告中的机构（organization/orgName）是否与 JSON 原始字段**逐字一致**——若 `organization` 为空则取 `source` 字段；不得将来源类型标签（如"机构研报""微信"）填入机构字段。

---

## 二、数值精确性核验

### 2.1 财务数据交叉验证

- [ ] 提取报告中§7（财务与盈利质量）表格的所有数值。
- [ ] 对于港股：与 `structured.hk_financials.getHkFdmtIsPit` / `getHkFdmtBsPit` / `getHkFdmtCfPit` 中对应年份数据逐一比对，容差 ±1%（四舍五入差异可接受）。
- [ ] 对于美股：与 `research.details` 中各研报摘要中的数值交叉验证，确认数字来源可追溯。
- [ ] 标注："FY20XX 营收报告为 X，JSON 中为 Y（偏差 Z%）"。

### 2.2 估值数据核验

- [ ] §11.1 机构目标价：与 `research.details` 中每篇研报的 `targetPrice` 字段比对。
- [ ] §11.1 评级：与 `research.details` 中 `rating` 字段比对（注意中英文映射：买入=Buy，增持=Overweight，中性=Neutral）。
- [ ] 当前股价/市值：与最新搜索材料比对日期和数值。
- [ ] PE/估值倍数：检查是否标注口径（TTM / NTM / FY2026E），不同口径数值不应混淆。

### 2.3 业务数据核验

- [ ] §5.2 分业务收入数据：与研报/接口中的 segment breakdown 比对。
- [ ] 同比增速：手工验算（当年-上年）/ 上年，偏差 >1ppt 则标注。
- [ ] 占比：各业务占比之和是否为 100%（±1%容差）。

---

## 三、事实属性与指标口径核验

### 3.1 Forecast / Guidance / Actual 区分

- [ ] 提取正文中所有"发布/上线/实现/完成/已"等已发生表述，逐条回查来源是否确认为实际发生。
- [ ] 若来源只写"预计/预期/有望/或将/目标价/预测"，正文是否保留预测属性；不得写成已发布、已上线、已实现。
- [ ] 目标价、盈利预测、情景推演中的数字是否明确标注为预测或假设，且引用紧跟数字。

### 3.2 指标口径一致性

- [ ] `资本开支`是否全篇只使用一个主口径；若同时出现公司披露 CapEx、研报口径 CapEx、现金流量表"购建长期资产支付现金"，是否分别命名并解释差异。
- [ ] `ROE`是否使用常规定义或接口直接披露值；若正文用"税前利润/期末净资产"，是否已改名为该算法本身。
- [ ] 风险提示中的资产、投资、现金流等数字是否使用最新报告期；若使用旧期数据，是否说明原因。

---

## 四、结构性合规核验

### 4.1 章节完整性

- [ ] 报告是否包含全部 13 个章节，按顺序：标题→1关键要点→2近况跟踪→3核心投资逻辑（3.1/3.2）→4催化事件→5业务拆分（5.1/5.2/5.3）→6产销链→7财务→8市场关注→9行业对比→10市场分歧→11估值（11.1/11.2/11.3/11.4）→12风险→13参考资料。
- [ ] 检查是否有多余章节或缺失章节。

### 4.2 表格列数合规

- [ ] 普通数据表列数 ≤ 8，行业对比表 ≤ 10。
- [ ] 公司+代码合并为一列（`公司名（代码）`），未分拆为两列。
- [ ] 参考资料是否为纯文本列表，不是 Markdown 表格。

### 4.3 特定章节规则

- [ ] §5.2：若某年所有业务行均无分业务数据，该年三列（收入/占比/毛利率）是否已隐藏。
- [ ] §8 美股：是否只有"市场关注"表格，没有"调研大纲/调研问题"。
- [ ] §8 港股：是否在市场关注表后有 3-4 个议题。
- [ ] §9：是否按 10 列新模板：`竞争关系|公司(代码)|市场|可比业务|行业地位|相关业务进展|市值|商业模式|目标客户群体|核心产品`。
- [ ] §9：相关业务进展是否具体可验证（含数字/事件），非笼统描述。
- [ ] §9：每个可比公司行是否至少有一个来源；市值是否注明日期，私有公司估值是否避免写成确定事实。
- [ ] §11.2：所有行是否均有具体数值；仅有定性描述的行是否已移除。
- [ ] §11.4：三种情景概率之和是否为 100%。
- [ ] §13：参考资料格式是否统一为 `[N] 类型 | 日期 | ID：xxx | 机构 | 标题 | API：xxx`。

---

## 五、引用位置规范性核验

- [ ] 所有 `[N]` 是否紧跟在**数值**后（如 `16.82港元[23]`），而不是挂在机构名、指标名、评级等非数值列。
- [ ] §11.1 表格中，`[N]` 是否在目标价数值所在单元格内，不在机构名/估值方法/评级/关键假设列。
- [ ] §11.2 表格中，`[N]` 是否在预测数值所在单元格内，不在来源列。
- [ ] 参考资料表格（若有）中是否有引用挂错位置的情况。

---

## 六、措辞与格式规范核验

- [ ] 正文是否无"未披露""未列""未提供""无数据""N/A"等填空式措辞。
- [ ] 所有数字句是否都有来源标注 `[N]`（无来源数字即红线）。
- [ ] 正文是否未出现具体券商/机构名称（§11.1 除外）。
- [ ] 序号格式：是否使用 `1）2）` 或 `•`，无 `1、2、3` 中文序号。
- [ ] 一句话结论约 20 字、最多 25 字，未被截断。

---

## 七、跨市场一致性核验

- [ ] 标题格式：港股→`{公司名}（{ticker}）港股公司一页纸：{结论}`，美股→`{公司名}（{ticker}）美股公司一页纸：{结论}`。
- [ ] 货币单位：港股用港元/人民币标注清楚，美股用美元，未混用。
- [ ] 财务口径：港股是否优先用 PIT 三大报表接口数据；美股是否标注 GAAP/non-GAAP 区分。

---

## 八、v1.2.3 新增核验项

### 8.1 章节编号核验

- [ ] 提取所有 H2 标题及其编号，与对应市场模板逐一比对。
- [ ] 提取所有 H3 标题，检查每个 H3 编号前缀 = 其上方最近 H2 的编号。
- [ ] 检查同级小节编号是否连续、无重复、无倒序。

### 8.2 稀疏行列核验

- [ ] 逐表检查：任一数据行 ≤1 个有效数据 → 该行是否已删除。
- [ ] 逐表检查：任一数据列 ≤1 个有效数据 → 该列是否已删除。
- [ ] 删除后检查：不足 2 个有效指标或 2 个比较维度 → 整张表是否已删除。
- [ ] 报告中是否无 `—`、`N/A`、空格、"待补充"、"已隐去"、"因数据不足删除"。
- [ ] 纯定性表（风险/多空观点）豁免本项检查。

### 8.3 数据优先级核验

- [ ] 每张表格是否有数据来源记录，是否在至少尝试到第 5 级（公告/纪要/披露）后才放弃。
- [ ] 是否存在"第一接口无数据即输出空表"的情况。

### 8.4 行内引用完整性核验

- [ ] 核心结论段落的每句事实/数字是否均有 `[N]`。
- [ ] 财务表格中的每个数值是否均有 `[N]`。
- [ ] 经营指标、行业格局、盈利预测、估值、催化剂和风险中的具体数字/事实是否均有 `[N]`。

### 8.5 参考资料格式核验

- [ ] 每条参考资料的 `[N]` 后是否**无空格**（`[1]Materials` 非 `[1] Materials`）。
- [ ] 字段顺序是否固定：`[N]`类型 | 日期 | ID：值 | 机构 | 标题 | API：值。
- [ ] 所有元数据是否从 materials JSON 逐字复制（标题/机构/日期/ID 不可改写）。
- [ ] 公开来源是否有完整 URL，是否无伪造的材料 ID。
- [ ] 结构化接口引用是否省略 `ID：` 字段但保留 `API：` 字段。

### 8.6 派生测算核验

- [ ] 所有内部测算是否有"内部测算"或 `Derived` 标注。
- [ ] 是否写明基础数据、公式、单位、假设。
- [ ] 无法完整复核的派生测算是否已删除具体数字，仅保留定性判断。

### 8.7 特殊行业适配核验

- [ ] 保险公司：是否使用 NBV/EV/P- EV/偿付能力等指标体系，是否无毛利率/库存/普通 PE。
- [ ] 银行/科技/周期/REITs 等：是否使用该行业适配指标体系。
- [ ] 是否无"套用不适用指标"的情况。

- [问题描述]

### 通过项（X / 总Y项）
